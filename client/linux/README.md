# Linux desktop client (Issue #132)

Status: experimental source build. This is distinct from the published Linux server archives; it is not yet a validated release client.

Target: Ubuntu 24.04+ and Fedora with GTK 4, GLib, libsoup 3, JSON-GLib, libsecret and a running Secret Service session (GNOME Keyring or KDE Wallet). The baseline is the distribution's glibc; no bundled libc, static portability, Arch package, .deb or .rpm is claimed. Install build dependencies (`valac meson ninja-build libgtk-4-dev libsoup-3.0-dev libjson-glib-dev libsecret-1-dev` on Ubuntu), then `meson setup client/linux/build client/linux && meson compile -C client/linux/build`. `meson install -C client/linux/build` installs the binary; remove it to uninstall. Upgrades rebuild/reinstall the binary, leaving server data and Secret Service items untouched. The unsigned source build is not a trusted/signed distribution artifact; use packages from a trusted source and verify TLS certificates.

Discovery defaults to `https://127.0.0.1:8443` (the packaged server's loopback address). A different origin must be entered explicitly, uses HTTPS, and is validated by the system trust store. Self-signed development certificates need explicit trust configuration outside the app; there is no accept-any-certificate switch. Login sends a password only over HTTPS and clears the entry after use. A session cookie is scoped to server origin, account and credential type in Secret Service (`org.momentum.credentials`); the password is never persisted. Restore session requires the user to re-enter origin/account. Logout contacts the server to revoke the cookie before clearing Secret Service; if the server cannot be reached it reports incomplete revocation and preserves the cookie for a later retry. No plaintext fallback is implemented: headless users must use a supported Secret Service provider rather than an unreviewed encrypted-file implementation.

The versioned API provides capabilities, default-backend tasks, optimistic conditional status/deletion, and open sync conflict count. Refresh provides server-current state; stale mutations are rejected with 409, not silently overwritten. The native UI is intentionally limited: task detail editing, multi-backend selection, conflict resolution, drag-and-drop and rich filtering are not yet implemented. Server-side provider sync scheduling is separately tracked. Do not describe this as feature-complete or release-ready until those gaps and the #130 release-binary/upgrade validation contract are met.
